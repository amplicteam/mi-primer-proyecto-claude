    Create amplic-learn/src/lib/stores/user.svelte.ts — a Svelte 5 runes module store for the
    active user. Use a `$state` object (e.g. `let state = $state<{ activeUserId: string | null }>(...)`)
    exported via a factory or exported getters/setters object. Requirements:
    - Import `browser` from "$app/environment" and guard ALL localStorage access (SSR safety —
      localStorage is undefined on the server).
    - Persist the active user id under localStorage key `amplic:active-user`.
    - On init (browser only), hydrate activeUserId from localStorage if present.
    - Expose: a getter for the active profile (resolve id -> Profile from profiles.ts, returns
      null if unset), `setActiveUser(id: string)` (validates id is a known profile, writes to
      localStorage), and `clearActiveUser()` (for "Cambiar usuario" — removes the key, resets state).
    - Export a single store instance the rest of the app imports.

    Create amplic-learn/src/lib/stores/progress.svelte.ts — a runes module store for per-user
    progress. Requirements:
    - Import `browser` from "$app/environment"; guard all localStorage access.
    - Storage key is NAMESPACED per user: `amplic:progress:${userId}` (e.g. amplic:progress:dharrell).
      This is the critical link — Dharrell and Jose must never read the same key (CORE-03, PROG-04).
    - Internal state: a record/map of resourceId -> UserProgress for the CURRENTLY loaded user.
    - `loadFor(userId: string)`: read that user's key from localStorage, parse JSON, populate state.
      Called when the active user changes.
    - `isCompleted(resourceId: string): boolean` — getter for a resource's completed flag.
    - `toggle(userId: string, resourceId: string)`: flip completed, set completedAt to ISO string
      or null, persist to that user's namespaced key. (Phase 3 catalog will call this.)
    - On the server / before browser hydration, return safe empty defaults (no crash).

    Do NOT store derived/aggregate values (percentages, counts) — those are computed in Phase 4
    from raw completion records (per RESEARCH "All computed values derived from raw completion
    records -- never stored"). Do NOT use writable()/svelte/store — runes only.
